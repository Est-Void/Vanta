# Vanta

Linux-ассистент в духе Copilot: ИИ-помощник, который не просто отвечает на вопросы, а **работает с вашей системой**. Запускает команды в терминале, управляет устройством, имитирует ввод мыши и клавиатуры, анализирует содержимое экрана и воспринимает голосовые команды.

```
┌───────────┐        HTTP/JSON + SSE
│   CLI     │──────────────┐
│  (vanta)  │              │
└───────────┘              ▼
                     ┌───────────┐
┌───────────┐  Unix  │   Демон   │      ┌───────────────┐
│   GUI     │ socket │  (vantad) │──────│   LLM / Модель │
│(vanta-gui)│───────▶│           │      └───────────────┘
└───────────┘        └─────┬─────┘
                           │
        ┌────────┬─────────┼──────────┬──────────┐
        ▼        ▼         ▼          ▼          ▼
     Терминал  Устройство  Ввод     Экран      Голос
      (PTY)    (power/   (X11/    (скрин-    (STT/TTS)
               network)  Wayland)  шоты/OCR)
```

---

## Возможности

- **Терминал и шелл-команды** — запуск команд, интерактивные PTY-сессии, стриминг вывода в реальном времени.
- **Шелл-интеграция** — через CLI/TUI-команды: «объясни команду», «исправь ошибку», пайп вывода в ассистента.
- **Управление устройством** — питание, сеть, аудио, дисплеи, процессы, пакеты.
- **Имитация ввода** — эмуляция клавиатуры и мыши через X11/Wayland и uinput.
- **Анализ экрана** — снятие скриншотов, распознавание содержимого (OCR/vision).
- **Управление окнами** — фокус, раскладка, виртуальные рабочие столы (EWMH, скрипты KWin/GNOME Shell).
- **Анализ логов и отладка** — чтение journalctl, разбор ошибок, диагностика проблем по журналам.
- **Event-driven автоматизация** — правила-триггеры: «при условии X — выполнить Y» (метрики, события, файлы).
- **Голосовые команды** — распознавание речи (STT) и озвучивание ответов (TTS).
- **Память и знания (RAG)** — запоминает проекты и предпочтения, семантический поиск по локальным документам.
- **Контекстная помощь** — ассистент знает окружение: систему, запущенные процессы, состояние файлов.

## Архитектура

### Компоненты

| Компонент | Описание |
|---|---|
| **vantad** (демон) | Единственный процесс с привилегиями доступа к системе. HTTP-сервер на Unix-сокете, SSE-стриминг, маршрутизация запросов к модулям. |
| **vanta** (CLI) | Интерактивный чат в терминале. Пересылает сообщения демону, отображает потоковые ответы. |
| **vanta-gui** (GUI) | Нативный WebView с веб-фронтендом внутри. Go-бэкенд обслуживает встроенный веб-интерфейс и ходит к демону по тому же протоколу, что и CLI. |

### Модули демона (`internal/modules/`)

| Модуль | Ответственность |
|---|---|
| `terminal` | PTY-сессии, выполнение шелл-команд, стриминг stdout/stderr, размер терминала |
| `device` | Управление устройством: питание, сеть, аудио, дисплеи, процессы, пакетные менеджеры |
| `input` | Имитация клавиатуры и мыши (X11/Wayland, uinput/XTest) |
| `screen` | Скриншоты, анализ содержимого экрана, OCR |
| `voice` | Запись микрофона, STT, TTS |
| `agent` | Логика ассистента: выбор инструментов, планирование шагов, интеграция с LLM |
| `auth` | Аутентификация клиентов, скоупы прав, контроль доступа |

### Схема каталогов (предлагаемая)

```
cmd/vanta/          CLI-клиент
cmd/vantad/         демон
cmd/vanta-gui/      GUI: Go-бэкенд + WebView (см. ниже)
internal/daemon/    HTTP-сервер, сокет, маршрутизация
internal/transport/ протокол: REST + SSE, типы запросов/ответов
internal/modules/   модули (см. таблицу выше)
pkg/api/            публичные типы протокола (JSON-схемы)
web/                статические ресурсы веб-фронтенда GUI
```

### vanta-gui (Go + WebView)

GUI — это чат-интерфейс: список сообщений, markdown-рендер, стриминг ответов агента через SSE, кнопка Stop. Вся бизнес-логика живёт в Go-бэкенде внутри процесса `vanta-gui`: он открывает Unix-сокет к демону, держит SSE-подписки и проксирует их в веб-интерфейс. Сам веб-фронтенд — это HTML/JS/CSS (собранные статические ресурсы), отображаемые в нативном WebView.

```
┌─────────────────────────────── vanta-gui ───────────────────────────────┐
│  WebView                        Go backend                              │
│  ┌─────────────┐    binding    ┌─────────────────────────┐   Unix socket │
│  │  Веб-UI      │◀────────────▶│ bindings/API, SSE-proxy │◀─────────────▶│ vantad
│  │ (HTML/JS)    │  (JSBridge)  │ (чаты, вложения, голос) │               │
│  └─────────────┘               └─────────────────────────┘               │
└───────────────────────────────────────────────────────────────────────────┘
```

**Вложения (drag&drop):** файлы загружаются отдельным запросом `POST /v1/attachment` и ссылаются из сообщения по `att_id`. Перетаскивание из файлового менеджера (через бэкенд) и кнопка «прикрепить» (нативный `OpenFileDialog`), вставка картинок из буфера обмена. Тип вложения определяет обработку: `image/*` → vision, текст/PDF/офис → извлечение в контекст, прочие → путь к файлу для `terminal`. Файлы хранятся в `~/.local/state/vanta/attachments/`.

**Голосовой ввод:** запись микрофона через модуль `voice` демона (PulseAudio/PipeWire, без захвата медиа в WebView) → STT → распознанный текст в поле ввода.

## Протокол

- **Транспорт:** HTTP/JSON поверх Unix-сокета (путь по умолчанию: `/run/user/$UID/vanta/vanta.sock`).
- **Стриминг:** Server-Sent Events (SSE) для потоковых ответов, вывода терминала и событий агента.
- **Долгие операции** (например, работа агента) начинаются с REST-запроса и возвращают `EventSource`, по которому клиент читает события.

Пример эндпоинтов:

```
POST /v1/session                     создать сессию
POST /v1/session/{id}/message        отправить сообщение агенту (SSE-стрим)
POST /v1/attachment                  загрузить вложение (файл/картинку), вернуть att_id
POST /v1/terminal                    создать PTY-сессию
POST /v1/terminal/{id}/input         ввод в сессию
GET  /v1/terminal/{id}/stream        SSE-поток вывода
POST /v1/screen/capture              снимок экрана
POST /v1/input/mouse                 событие мыши
POST /v1/input/key                   нажатие клавиши
GET  /v1/device/info                 информация об устройстве
POST /v1/voice/transcribe            распознать речь
GET  /v1/events                      глобальный SSE-поток событий
```

Пример сообщения с вложением:

```json
{
  "id": "m1",
  "session": "s1",
  "role": "user",
  "content": "посмотри на скриншот",
  "attachments": [{"id": "a1", "name": "shot.png", "type": "image/png", "size": 12345}]
}
```

### Безопасность

- Сокет создаётся с правами `0600`, доступен только владельцу.
- Токен аутентификации у клиентов, скоупы прав (какие модули доступны клиенту).
- Демон не требует root; операции, требующие привилегий, отдельно конфигурируются.
- Действия агента подтверждаются клиентом там, где это необходимо.

## Интеграция в систему

### Уровень 1 — базовая программа

| Требование | Реализация |
|---|---|
| Бинарник в PATH | `/usr/local/bin` (системно) или `~/.local/bin` (пользователь); дистрибутивная сборка через goreleaser (deb/rpm/Arch) |
| Конфиг (XDG) | `~/.config/vanta/config.toml` + системный `/etc/vanta/config.toml`, koanf/Viper |
| Логи | `~/.local/state/vanta/*.log` (slog); для сервиса — `journalctl --user -u vanta` |
| История | `~/.local/state/vanta/history.jsonl` (append-only: сессии, команды, действия агента) |
| man / `--help` | CLI на cobra: `--help` из коробки, `genManTree` → `/usr/share/man/man1/vanta.1.gz` |
| Shell completions | cobra: `vanta completion bash|zsh|fish` → `/usr/share/bash-completion/completions/` |

### Сервис и автозапуск

Два активационных пути к одному демону:

1. **systemd user unit** `~/.config/systemd/user/vanta.service` c `WantedBy=default.target` — автозапуск демона в пользовательской сессии.
2. **Socket activation** `vanta.socket` на `/run/user/$UID/vanta.sock` — демон поднимается по первому подключению, не ест ресурсы в простое.
3. **D-Bus activation** для GUI: `/usr/share/dbus-1/services/org.vanta.Vantad.service` + `DBusActivatable=true` в desktop-файле — старт по первому вызову.
4. **Desktop entry** `/usr/share/applications/vanta.desktop` — GUI-клиент в меню приложений.

### D-Bus и уведомления

- Демон экспонируется на шине сессии: имя `org.vanta.Vantad`, методы `SendMessage`, сигнал `StreamEvent` (лёгкий доступ для hotkey-daemon, виджетов, уведомлений в дополнение к Unix-сокету).
- Уведомления через `org.freedesktop.Notifications`: долгие операции, запросы подтверждения, завершение задач агента.

### Глобальные горячие клавиши

- **Wayland:** обычные приложения не могут грабить клавиши — только XDG Desktop Portal `org.freedesktop.portal.GlobalShortcuts` (`CreateSession`/`BindShortcuts`, сигнал `Activated`). Поддержка: KDE (Plasma 5.27+), GNOME (47+).
- **X11:** фолбэк через `XGrabKey`.
- **Клавиша ассистента (Copilot):** ядро Linux резервирует под неё сканкоды `KEY_COPY` (0x15f) и `KEY_OPEN` (0x160) — конкретный приходит непредсказуемо, поэтому слушаем оба (evdev в `input`-модуле) → активация ассистента. Запасное сочетание (например, Super+Space) для железа без клавиши.

### Скриншоты (поправка под Wayland)

Прямой захват экрана на Wayland недоступен: скриншот-модуль идёт через `org.freedesktop.portal.Screenshot` (или PipeWire), под X11 — фолбэк `XGetImage`.

### Доступность (accessibility)

- Взаимодействие с текстовыми полями и элементами UI через **AT-SPI2** (over D-Bus): дерево окон, фокус, чтение/запись текста, курсор (`org.a11y.atspi.Text`).
- Поиск элементов «кнопка с подписью X» → связка с `screen`-модулем: AT-SPI для точности, OCR — фолбэк для приложений без a11y (Qt-мост, Electron, игры).

```
systemd (user) ── vanta.socket ──► vantad
D-Bus activation ────────────────► vantad / vanta-gui
   │
   ├── org.freedesktop.Notifications          (уведомления)
   ├── org.freedesktop.portal.GlobalShortcuts (hotkey, Wayland)
   ├── org.freedesktop.portal.Screenshot      (скриншоты, Wayland)
   └── org.a11y.Bus / atspi                   (текстовые поля, элементы UI)
```

## Технологический стек

- **Язык:** Go
- **GUI:** Go-бэкенд + веб-фронтенд в нативном WebView (Wails)
- **CLI:** cobra (man-страницы, shell completions)
- **Конфиг:** koanf/Viper (TOML, XDG)
- **PTY:** `github.com/creack/pty`
- **D-Bus:** `github.com/godbus/dbus` (сервис демона, уведомления, порталы)
- **Ввод (X11/Wayland):** XTest / uinput (нативный код)
- **Скриншоты:** `org.freedesktop.portal.Screenshot` (Wayland), X11-фолбэк
- **Доступность:** AT-SPI2 (over D-Bus)
- **STT/TTS:** интеграция через локальные модели (например, whisper.cpp) или облачные API — обсуждается
- **LLM:** pluggable-бэкенды (локальные модели, OpenAI-совместимые API)
- **RAG:** эмбеддинги + векторный поиск (например, sqlite-vec / локальные модели эмбеддингов)
- **Автоматизация:** триггеры через inotify, метрики системы, события D-Bus
- **Упаковка:** goreleaser (deb/rpm/Arch), systemd unit-ы

## Сборка и запуск

> Будут добавлены после реализации Фазы 0.

```bash
make build          # собрать vantad, vanta и vanta-gui
sudo make install   # установить демон и systemd-юнит
vantad &            # запуск демона (или через systemd)
vanta               # запуск CLI
vanta-gui           # запуск GUI
```
